# ADR-017: Starter single-server hosting for the Oxinov Edu launch

**Date:** 2026-09-26. **Status:** Accepted; its Docker Compose runtime is superseded by k3s on the same server under ADR-018 the same day (owner decision of 2026-09-26: "Starter", about US$25–45 a month). Until paying schools depend on Oxinov Edu, production runs on one EC2 server (`t3a.medium`, 4 GiB, Mumbai) managed by `devops/terraform/environments/production/starter`, instead of the ADR-009 baseline of ECS Fargate, RDS, and ElastiCache (about US$150–250 a month). Docker Compose (`devops/starter/`) runs PostgreSQL 18, Keycloak at `id.oxinov.com`, the Edu and platform APIs, `edu.oxinov.com` and `app.oxinov.com`, and Caddy, which is the only service with open ports (80 and 443) and obtains Let's Encrypt certificates. The server has no SSH: administrators use Systems Manager Session Manager, and the Keycloak administration console and master realm return 404 publicly. Containers use the instance role (IMDSv2, hop limit 2), so no AWS access keys exist: lesson media live in a private, versioned S3 bucket with signed URLs, and sign-in emails go through a small SMTP-to-SES relay (`backend/workers/mail-relay`) that accepts only `no-reply@oxinov.com`. Application secrets are generated on the server into Parameter Store SecureStrings on the first deploy, never in Terraform state or GitHub. Recovery: nightly `pg_dumpall` to S3 (30 days), daily encrypted disk snapshots (7 days), CloudWatch recover and reboot actions, and daily automatic security updates. Releases are built, scanned with Trivy, and pushed to immutable ECR tags by `.github/workflows/deploy-production.yml`, which runs the deploy script over Systems Manager with a keyless OIDC role.

Consequences: one server is a single point of failure (a host fault means minutes of downtime; losing the disk means restoring the latest snapshot or dump, up to 24 hours of data); there is no WAF or CDN in front of the apps yet; capacity is limited to early schools. Move to the ADR-009 layout when a paying school needs an availability commitment, sustained load exceeds the server, or data volume makes restores slow; the images, migrations, and settings carry over unchanged. Alternatives considered: Lightsail (cheaper, but no instance roles, so long-lived keys), the full ADR-009 stack now (cost before revenue), and SES SMTP credentials (long-lived keys instead of the relay).
