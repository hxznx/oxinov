# CI/CD pipeline

Current workflows validate the documentation scaffold and security conventions and use Trivy to scan the repository for high/critical vulnerabilities, secrets, and misconfiguration. The `api` job in `ci.yml` type-checks, lints, and unit-tests `backend/api`, applies migrations to a PostgreSQL 18 service, fails on Prisma schema drift, runs the SQL row-level-security tests and the API integration tests as `oxinov_app`, then builds. As more apps arrive, enable these required gates: lint/format, strict TypeScript, CodeQL, dependency review, domain and PostgreSQL integration tests, OpenAPI compatibility, migration rehearsal, SBOM/provenance, image build and scan, web/mobile smoke tests, Prometheus rule validation, Grafana provisioning checks, and SOC event/detection tests.

Release flow: main branch -> immutable images -> staging migration/deploy -> smoke tests -> synthetic monitoring alert -> approved production promotion -> monitoring. Android is built from the same release branch as a signed `.aab` for internal testing, then promoted through Play tracks after store checks. The checked-in `deploy.yml` is intentionally gated until a cloud target and secrets are configured.
