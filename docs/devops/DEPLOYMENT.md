# Deployment architecture

Docker images: frontend, backend, worker, and chat. PostgreSQL runs in Docker on durable encrypted storage with backup and restore procedures; Redis is disposable. TLS ingress routes tenant subdomains and verified custom domains. Private networks protect database, queue, exporter, and application metric endpoints. Object storage and Mux hold files/video.

Compose supports local and initial single-host deployments. The root `docker-compose.yml` is the developer entry point and uses `devops/docker/Dockerfile` for application images. The local `monitoring` profile runs Prometheus, Alertmanager, Grafana, and database/cache exporters. For production, select managed or highly available metric storage, durable retention, authenticated Grafana access, encrypted alert receivers, and an owner for each alert before launch. Kubernetes manifests in `devops/kubernetes/` are templates for a later orchestrated topology and are not production-ready until image registry, ingress, secrets, persistent volumes, monitoring discovery, and provider settings are selected. Terraform and Ansible under `devops/` are similarly unconfigured. See [architecture](../architecture/ARCHITECTURE.md) and [observability](OBSERVABILITY.md).

The SOC platform is deployed separately from the application and operational monitoring plane. Production deployment must provide private/encrypted event ingestion, analyst MFA and RBAC, retention/residency controls, immutable administrative audit, tested alert delivery, and protected evidence storage. Falco belongs to production Linux/Kubernetes runtime deployment; do not add its required host capabilities to the local application Compose profile.
