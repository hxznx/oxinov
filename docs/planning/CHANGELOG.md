# Project changelog

- **2026-09-26, v1.40:** Oxinov Edu books and resources (FR-COURSE-202/204). Migration `20260926000100_lesson_resources` adds `resource_files` (checked uploads under the tenant's prefix) and `lesson_resources` (a file or an http(s) link per lesson version, enforced by constraints), both tenant-isolated. Teachers upload PDF, EPUB, Word, PowerPoint, Excel, image, text, and ZIP documents up to 100 MB by signed URL with a size and content check, or add links, then rename or remove them on draft lessons; resources publish with the course and are copied into new drafts (lessons now get their IDs up front so their resources follow). Learners with course access and teachers get short-lived links to download, and to read PDFs in the browser from the storage domain; free previews never show resources. `lms-web`: a resources box in the lesson editor with upload progress and automatic titles, and a Books and resources list under each lesson. Verified: unit 27/27 and 26/26, integration 60/60 (3 new against SeaweedFS), and live from upload to a learner opening the PDF. One full integration run had four failures that did not reproduce in two further full runs; CI will show whether a test is timing-sensitive.
- **2026-09-26, v1.39:** Oxinov Edu personal notes (FR-PLAYER-403). Lessons gain a stable `lineage_id` that new drafts copy, so learner data follows a lesson across course versions (the migration links existing draft copies to their published lessons). Migration `20260925000500_lesson_notes` adds `lesson_notes` with owner-only row-level security: not even the course teacher or the tenant owner can read or change a learner's notes (database policy tests cover it). Edu API `notes` module: create, list, edit, and delete notes on lessons the learner can open (preview lessons included), optionally at a video or audio moment, and list a course's notes in curriculum order, with notes on removed lessons last. `lms-web`: a notes panel under each lesson (link to the current moment, click a time to jump the player, edit, delete), a course notes page, a Markdown download, and a print layout for saving as PDF. Verified: unit 27/27 and 24/24, integration 57/57 (3 new, including notes surviving a republish), database policy tests, and live at phone width.
- **2026-09-25, v1.38:** Oxinov Edu assignments (FR-ASSESS-503). Migration `20260925000400_assignments` adds `assignments`, `assignment_submissions` (each learner's private draft), and `submission_revisions` (every submitted version with the teacher's decision), with row-level security that shows a learner only their own work, lets the tenant's teaching staff read and grade (`app_is_tenant_staff()`), and stops learners from inserting graded revisions or changing grades; the database policy tests cover it. Edu API `assignments` module: teachers of the course create, edit, open, and close assignments (text, link, and file answers, due date, late policy, file size limit, optional points), see submissions (never drafts), and grade the latest version as passed, not passed, or revision requested (feedback required); learners with course access save drafts, attach files by signed upload with a content check (PDF, Office, images, text, ZIP, audio; HTML and scripts refused), and submit before the deadline or late when allowed. Files download only as attachments. `lms-web`: assignments on the course page, the learner's assignment page with draft, upload progress, submit, and version history with feedback, and teacher pages for settings (deadline entered in local time), submissions, and grading. Verified: unit 27/27 and 21/21, integration 54/54 (5 new, including real file uploads), database policy tests, and live at phone width from creating an assignment to a requested revision.
- **2026-09-25, v1.37:** Oxinov Edu quiz builder (FR-ASSESS-501/502). Edu API `quizzes` module, with no schema change: teachers create practice quizzes and mock exams for their own courses (administrators for all), set time limit, pass mark, attempts, answer release, and shuffling, add sections that draw a number of random questions from their own pool, and write single-choice, multiple-choice, true/false, and fill-in-the-blank questions with explanations and marks (validated with clear messages). Publishing needs every pool to be large enough; once anyone has taken a quiz its settings and sections are frozen (close it or copy it, and copies share the question pools), while questions can still be corrected (the version increases and attempts keep their own copy) or retired if the pool stays large enough. Courses without a question bank get their own. `lms-web`: quiz list and creation in the course editor and a quiz builder page with status actions, settings, sections, and a question form that adapts to the question type. Verified: unit 24/24 and 19/19, integration 49/49 (4 new), and live in the browser from an empty quiz to a learner scoring 100% and the structure locking.
- **2026-09-25, v1.36:** Oxinov Edu video and audio lessons (FR-COURSE-202/205, FR-PLAYER-401/402/404). Local object storage moves from MinIO, whose images are no longer published, to SeaweedFS 4.47 (digest-pinned, keys written inside the container from `.env`, `-volume.max=0`); `OBJECT_STORAGE_*` settings replace `MINIO_*`. Migration `20260925000300_lesson_media` adds `media_assets` (tenant-prefixed object keys, size and duration checks) and `media_progress` (row-level security limits each row to its own learner). Edu API `media` module with the AWS SDK: signed direct uploads for MP4 and WebM video (1 GB) and MP3, M4A, OGG, and WebM audio (200 MB), then a completion check of size and file signature that deletes impostors; checksums only when required, so browser uploads work. Video and audio lessons attach a READY file of the same kind from the same tenant, need a transcript or text alternative before review, and learners get a 10-minute signed playback URL only after the lesson access check, plus resume and completion (90% actually played, at most 30 seconds per save, seeks never count). `lms-web`: lesson type choice, an uploader with progress that measures duration in the browser, and a player with speed from 0.5× to 2×, resume, saving every five seconds and on pause or close, and the transcript. Verified: unit 20/20 and 15/15, integration 45/45 (3 new media tests against SeaweedFS, also added to CI), database policy tests, and live in the browser from upload to published lesson and resume.
- **2026-09-25, v1.35:** Oxinov Edu teacher editing (FR-COURSE-201/202/203). Edu API `authoring` module: list editable courses, open a draft (copying the published version into a new version), edit details and price, add, rename, and delete chapters, add, edit, and delete text lessons, reorder chapters and lessons (lessons may move between chapters; positions swapped safely under their unique constraints), send for review, withdraw, and approve or send back with feedback; approval publishes the draft and supersedes the previous version in one transaction, and every step is audited. Instructors edit only their own courses; administrators edit and review all; learners are refused. Migration `20260925000200_course_review` adds submission time and reviewer feedback to course versions. `lms-web`: Teach page, course editor with move buttons and the review panel, and a Markdown lesson editor with a live preview that uses the same renderer as learners (no raw HTML). Verified: unit 17/17, integration 42/42 (3 new), and live in the browser from creating a course to a published lesson.
- **2026-09-25, v1.34:** Oxinov Edu join codes, like a class code (FR-AUTH-102, FR-TENANT). New `tenant_invites` table (migration `20260925000100_tenant_invites`) with forced row-level security: administrators see only their tenant's codes, and a person redeeming a code can read only the invite with exactly that code (`app.invite_code`); codes are 8 characters without look-alikes, never grant ownership, and keep their use counter within the limit. Edu API: create, list, and revoke codes and list members (administrators; only owners mint administrator codes), and `POST /v1/invites/redeem` for verified people, which joins once, consumes a use atomically, answers unknown, expired, used-up, and revoked codes identically, audits joins, and emits a security event for failed attempts. `lms-web`: "Join with a code" on the home page, shareable `/join?code=` links that survive sign-in, and a People page with code creation (role, expiry, people limit), copyable links, status, turning codes off, and the member list. Verified: unit 17/17, integration 39/39 (7 new), database policy tests with new invite checks, and live in the browser with an owner creating a code and a second person joining through the link.
