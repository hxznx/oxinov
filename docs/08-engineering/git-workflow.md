# Git workflow

Use short-lived feature branches and pull requests. A PR links requirement IDs, explains behavior and migration impact, and shows test evidence. Protect the main branch with review and CI. Use conventional, descriptive commits when practical; do not mix unrelated features in one PR.

**Status:** Current · **Owner:** Engineering lead · **Last reviewed:** 2026-09-29

Release immutable image tags from main. Tag mobile releases and keep their backend compatibility window documented. No force-push to protected branches. Repository hosting and branch protection remain to be configured.
