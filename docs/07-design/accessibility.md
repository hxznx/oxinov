# Accessibility

Web target: WCAG 2.2 AA. Test keyboard navigation, focus order, contrast, labels, errors, timers, captions, transcripts, and exam controls. Offer time accommodations where an exam policy permits them.

Android/iOS: test TalkBack and VoiceOver, dynamic text, touch targets, reduced motion, media controls, and permission prompts. Arabic right-to-left layouts must preserve correct reading order.

Automated checks do not replace manual assistive-technology tests. Record failures as release blockers when they prevent core learning or purchasing.

Include disabled people and people who need assisted-digital support throughout discovery, prototype testing, beta, and live research; do not wait for a final accessibility audit. Compare task success, time, ease, confidence, and recovery by context so an overall average cannot hide exclusion. Follow the [user-centred product standard](../12-research/user-centered-product-standard.md).
